Section 03

Environment variables

All values go in .env.local (git-ignored). Never commit secrets.

Clerk publishable key
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY

From Clerk Dashboard → API Keys. Starts with pk_test_ or pk_live_.

Clerk secret key
CLERK_SECRET_KEY

Server-only. Starts with sk_test_ or sk_live_. Never expose client-side.

Backend API URL
NEXT_PUBLIC_API_URL

Points to Django DRF. Local default: http://localhost:8000/api/v1

Stripe key
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY

Optional for now — finance module. Starts with pk_test_.

CDN URL
NEXT_PUBLIC_CDN_URL

CloudFront distribution for billboard media. Leave blank locally.

Auth redirects
NEXT_PUBLIC_CLERK_SIGN_IN_URL

Set to /sign-in and /sign-up. Post-auth lands on /.

.env.local
# Clerk
NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_your_key_here
CLERK_SECRET_KEY=sk_test_your_key_here
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in
NEXT_PUBLIC_CLERK_SIGN_UP_URL=/sign-up
NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL=/
NEXT_PUBLIC_CLERK_AFTER_SIGN_UP_URL=/

# Backend
NEXT_PUBLIC_API_URL=http://localhost:8000/api/v1

# Optional
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
NEXT_PUBLIC_CDN_URL=https://your-cloudfront-id.cloudfront.net
NEXT_PUBLIC_ENABLE_ANALYTICS=true
Section 04

Auth flow — Clerk

Clerk guards the app at three layers, so unauthenticated requests never reach your UI or the Django backend.

①

Edge middleware — src/middleware.ts

Runs on every request before the page renders. Public routes (/sign-in, /sign-up, /api/health) bypass auth; everything else is redirected to /sign-in.

②

Server component — (dashboard)/layout.tsx

Calls await auth() and redirects if userId is null. Double-checks even if middleware somehow passes a request.

③

API layer — src/lib/api-client.ts

Axios request interceptor calls window.Clerk.session.getToken() and attaches Authorization: Bearer <token>. The Django backend validates this JWT on every endpoint. A 401 response redirects to /sign-in.

⚠ Only use auth() (server) and useAuth()/useUser() (client) from @clerk/nextjs. Do not pass user tokens through props — always pull them from Clerk directly.
Section 05

Adding a new domain

The project follows a strict layered pattern — wire up a new API resource in exactly this order:

1. Typessrc/types/
2. Query keyslib/query-keys.ts
3. Hookhooks/use-*.ts
4. Pageapp/(dashboard)/*/

Example — adding Users:

src/types/user.ts (extend)
export interface User {
  id: 'string'
  email: 'string'
  role: UserRole
  // … other fields from the API
}
src/lib/query-keys.ts (add keys)
users: {
  all: () => ['users'] as const,
  list: (params?: UserFilters) => ['users', 'list', params] as const,
  detail: (id: string) => ['users', 'detail', id] as const,
  me: () => ['users', 'me'] as const,
},
src/hooks/use-users.ts (new file)
import { useQuery } from '@tanstack/react-query'
import { api } from '@/lib/api-client'
import { queryKeys } from '@/lib/query-keys'
import type { User } from '@/types/user'

export function useMe() {
  return useQuery({
    queryKey: queryKeys.users.me(),
    queryFn: () => api.get<User>('/users/me'),
  })
}
Section 06

Debugging in VS Code

Three launch configurations are pre-wired in .vscode/launch.json. Press F5 to run the compound config.

Config name What it does
Next.js: dev server Runs npm run dev with .env.local loaded
Next.js: debug (Chrome) Attaches Chrome debugger to localhost:3000 with webpack source maps
Next.js: debug server-side Attaches Node.js debugger on port 9229 for Server Components and API routes
Next.js: fullstack debug Compound — starts all three above simultaneously (use this daily)

React Query Devtools

A floating devtools panel is injected automatically in development (bottom-right). Click it to inspect cache entries, query states, and invalidation history. It is stripped from production builds.

Code quality

ESLint (.eslintrc.json)

Extends next/core-web-vitals, @typescript-eslint/recommended, @tanstack/eslint-plugin-query/recommended, and prettier. Key rules: consistent-type-imports, import/order with auto-sort, no-console (warn/error allowed), prefer-const.

Prettier (.prettierrc)

semi: false · singleQuote: true · tabWidth: 2 · trailingComma: "all" · printWidth: 100 · prettier-plugin-tailwindcss (sorts Tailwind classes automatically).

bash — pre-commit checklist
npm run type-check   # must exit 0
npm run lint         # must exit 0
