Section 0
Project Overview
Vizta Board is a full-stack SaaS billboard booking marketplace for African outdoor advertising. This guide gets a developer from zero to a fully running local environment covering all three layers of the platform.

Platform Architecture

vizta-board/ ├── backend/ # Django REST Framework API (Python 3.12) │ ├── apps/ # billboards, bookings, campaigns, payments, users │ ├── config/ # settings, urls, celery │ ├── docker-compose.yml # PostgreSQL 16 + Redis 7 │ ├── manage.py │ └── requirements.txt │ ├── mobile/ # Expo SDK 51 · React Native 0.74 · TypeScript │ ├── src/ │ │ ├── screens/ # Advertiser + Owner screen sets │ │ ├── components/ │ │ ├── navigation/ │ │ ├── services/ # Axios API client │ │ ├── hooks/ # useAuth (Clerk), useApi │ │ └── constants/ # design tokens │ ├── App.tsx │ └── package.json │ ├── web/ # Vanilla JS desktop SPA (no build step) │ └── index.html │ └── docs/ # TDD, ADRs, API reference

Technology Stack

LayerTechnologyVersionPurpose
APIDjango + DRF5.0 / 3.15REST endpoints, business logic, Celery tasks
AuthClerkLatestEmail + Google OAuth + TOTP MFA for all roles
PaymentsStripeLatestAdvertiser billing, 12 % commission flow
DBPostgreSQL16Primary relational store
Cache / QueueRedis + Celery7 / 5Task queue, caching, real-time updates
StorageAWS S3—Billboard image uploads
MobileExpo · React NativeSDK 51 / 0.74iOS + Android app
WebVanilla HTML/CSS/JS—Advertiser + Owner desktop portal
InfraAWS (EC2, RDS, S3, CF)—Production cloud hosting
💡
Each layer can be developed independently. If you only work on the web frontend, you only need Node.js + VS Code. Backend work needs Python + Docker. Mobile needs Android Studio additionally.

Setup Checklist

  • Backend .env file configured

  • Git pre-commit hooks installed
Section 1
System Prerequisites
Install the core system tools before setting up the individual project layers. Commands below target Ubuntu 22.04 LTS — adjust the package manager for other distros.
1
Install Git and configure identity
bash
sudo apt update && sudo apt install -y git

# Configure your identity (used in all commits)
git config --global user.name "Your Name"
git config --global user.email "your@email.com"
git config --global core.editor "code --wait"
git config --global init.defaultBranch main
2
Install Node.js v20 LTS via nvm

nvm lets you switch Node versions per project. The mobile app and web dev server both need Node 20.

bash
# Install nvm
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

# Reload shell, then install Node 20
source ~/.bashrc
nvm install 20
nvm use 20
nvm alias default 20

# Verify
node --version   # v20.x.x
npm --version    # 10.x.x
3
Install Python 3.12 via pyenv

pyenv manages Python versions cleanly, avoiding conflicts with the system Python.

bash
# Install build dependencies
sudo apt install -y build-essential libssl-dev libffi-dev \
  python3-dev zlib1g-dev libbz2-dev libreadline-dev \
  libsqlite3-dev curl git

# Install pyenv
curl https://pyenv.run | bash

# Add to ~/.bashrc
echo 'export PYENV_ROOT="$HOME/.pyenv"' >> ~/.bashrc
echo '[[ -d $PYENV_ROOT/bin ]] && export PATH="$PYENV_ROOT/bin:$PATH"' >> ~/.bashrc
echo 'eval "$(pyenv init -)"' >> ~/.bashrc
source ~/.bashrc

# Install Python 3.12
pyenv install 3.12.4
pyenv global 3.12.4

# Verify
python --version   # Python 3.12.4
4
Install Docker and Docker Compose

Docker runs PostgreSQL and Redis locally, matching the production environment.

bash
# Remove old versions
sudo apt remove -y docker docker-engine docker.io containerd runc

# Install via official script (simplest)
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

# Compose v2 is bundled with Docker Desktop; verify:
docker compose version   # Docker Compose version v2.x.x

# Log out and back in for group membership to apply, then verify:
docker run hello-world
⚠️
You must log out and log back in after adding yourself to the docker group, otherwise every docker command requires sudo.
5
Install Java 17 and Android Studio (mobile developers only)

Skip this step if you are only developing the backend or web frontend.

bash
# Java 17 (required by Android build tools)
sudo apt install -y openjdk-17-jdk
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64
echo 'export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64' >> ~/.bashrc

Download Android Studio from developer.android.com/studio, extract it, and run studio.sh. Inside Android Studio:

  • Go to SDK Manager → SDK Platforms → install API 34
  • Go to SDK Tools → install Android SDK Build-Tools 34, Platform-Tools, Emulator
  • Create a Virtual Device (AVD): Pixel 8 Pro · API 34 · x86_64
bash
# Add SDK paths to ~/.bashrc
echo 'export ANDROID_HOME=$HOME/Android/Sdk' >> ~/.bashrc
echo 'export PATH=$PATH:$ANDROID_HOME/emulator' >> ~/.bashrc
echo 'export PATH=$PATH:$ANDROID_HOME/platform-tools' >> ~/.bashrc
source ~/.bashrc

# Verify ADB can see the emulator (start the AVD first from Android Studio)
adb devices

Section 3
Django Backend
Set up the REST API, spin up PostgreSQL and Redis with Docker, run migrations, and start the development server.
1
Clone the repository
bash
git clone https://github.com/skaah-it/vizta-board.git
cd vizta-board
2
Create and activate a Python virtual environment
bash
cd backend

# Create venv (Python 3.12 via pyenv is the default)
python -m venv .venv

# Activate it
source .venv/bin/activate
# Prompt becomes (.venv) — required for every backend terminal session

# Install all dependencies
pip install -r requirements.txt

# Optional: install dev extras (testing, linting)
pip install -r requirements-dev.txt
💡
VS Code auto-detects .venv inside the workspace folder. Click the Python version in the status bar and select backend/.venv/bin/python if it is not already chosen.
3
Start PostgreSQL and Redis with Docker Compose
bash
# From the backend/ directory
docker compose up -d postgres redis

# Verify they are running
docker compose ps

Start the Django development server

Open http://localhost:8000/admin/ to confirm the Django admin loads. The REST API base is at http://localhost:8000/api/v1/.

To start the Celery worker in a second terminal (needed for async tasks like payment webhooks):

bash
# Second terminal, same backend/ directory with .venv activated
celery -A config worker -l info -c 4

Section 5
Web Frontend
The desktop web portal is a single self-contained HTML file — no build step, no bundler. Development is as simple as opening it with Live Server.
1
Open with VS Code Live Server (recommended)

With the Live Server extension installed (Section 2), right-click web/index.html in the Explorer and choose "Open with Live Server". The browser opens at http://localhost:3000 and reloads on every file save.

💡
The .vscode/settings.json from Section 2 already sets "liveServer.settings.root": "/web" and port 3000, so the server always starts from the correct directory.
2
Alternative: Python simple server

If you prefer not to use the extension, Python's built-in server works with no installation:

bash
python3 -m http.server 3000 --directory web/
# Open: http://localhost:3000
3
Connect the web frontend to the local Django API

Open web/index.html and locate the CONFIG block near the top of the <script> section. Update the API base URL:

javascript
const CONFIG = {
  API_BASE: 'http://localhost:8000/api/v1',
  CLERK_PUBLISHABLE_KEY: 'pk_test_xxxxxxxxxxxxx',
  STRIPE_PUBLISHABLE_KEY: 'pk_test_xxxxxxxxxxxxx',
};
⚠️
The Django server must be running and CORS must be configured. Add http://localhost:3000 to CORS_ALLOWED_ORIGINS in backend/config/settings/local.py.
python backend/config/settings/local.py
CORS_ALLOWED_ORIGINS = [
    "http://localhost:3000",   # Web frontend
    "http://localhost:8081",   # Expo web
    "http://10.0.2.2:8081",   # Expo from Android emulator
]
4
File structure and where to make changes

Everything lives inside web/index.html. The file is structured as:

index.html ├── <style> -- CSS custom properties (design tokens) │ ├── :root {} -- all color/type/layout tokens │ ├── @media dark {} -- dark mode token overrides │ └── component styles -- sidebar, cards, calendar, etc. │ ├── <div id="root"> -- render target │ └── <script> ├── CONFIG {} -- API base + keys ├── Mock data -- BILLBOARDS, CAMPAIGNS, OWNER ├── S = { ... } -- application state object ├── render() -- master orchestrator ├── renderSidebar() -- dark green 240 px rail ├── renderBrowse() -- billboard grid with search ├── renderDetailDrawer() -- right-side slide-in ├── renderBookingOverlay()-- 4-step booking flow ├── renderCampaigns() -- filterable campaign list ├── renderAnalytics() -- Chart.js 30-day chart ├── renderOwnerDashboard()-- KPI tiles + approve/reject └── handleClick() -- event delegation on #root

To replace mock data with live API calls, search for const BILLBOARDS and swap the hard-coded array with a fetch(CONFIG.API_BASE + '/billboards/') call.

4
Pull request checklist

Before opening a PR, confirm all of the following:

  • Branch is up to date with main — run git fetch origin && git rebase origin/main
  • All tests pass: cd backend && python manage.py test
  • No linting errors: cd mobile && npx eslint src/
  • No new migrations left un-committed
  • PR description references the issue number and describes the change
  • Screenshots or screen recording attached if UI changed
  • .env.example updated if new environment variables were added
