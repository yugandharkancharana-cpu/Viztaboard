01

Install Node.js via nvm

Use nvm (Node Version Manager) — it lets you switch Node versions cleanly and avoids permission issues with global npm installs.

bash — install nvm 
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash

After install, restart your terminal (or source your shell config), then:

bash 
# Reload shell config
source ~/.bashrc   # or ~/.zshrc if you use zsh

# Install Node 20 LTS and set as default
nvm install 20
nvm use 20
nvm alias default 20

# Verify
node -v   # → v20.x.x
npm  -v   # → 10.x.x
💡 Expo SDK 51 is tested against Node 18 and 20. Node 22 may work but can surface version mismatch warnings in some Expo CLI paths — stick with 20 LTS for a smooth experience.
02

Install VS Code

The fastest method on Debian/Ubuntu is Microsoft's own apt repo, which keeps VS Code auto-updated.

bash — Debian / Ubuntu 
# Add Microsoft GPG key and repo
wget -qO- https://packages.microsoft.com/keys/microsoft.asc \
  | gpg --dearmor \
  | sudo tee /usr/share/keyrings/microsoft.gpg > /dev/null

echo "deb [arch=amd64 signed-by=/usr/share/keyrings/microsoft.gpg] \
  https://packages.microsoft.com/repos/code stable main" \
  | sudo tee /etc/apt/sources.list.d/vscode.list

# Install
sudo apt update && sudo apt install -y code

# Launch
code .
bash — Fedora / RHEL / CentOS 
sudo rpm --import https://packages.microsoft.com/keys/microsoft.asc
sudo sh -c 'echo -e "[code]\nname=Visual Studio Code\nbaseurl=https://packages.microsoft.com/yumrepos/vscode\nenabled=1\ngpgcheck=1\ngpgkey=https://packages.microsoft.com/keys/microsoft.asc" > /etc/yum.repos.d/vscode.repo'
sudo dnf install -y code
💡 On Arch / Manjaro: yay -S visual-studio-code-bin  ·  On any distro: download the .deb or .rpm from code.visualstudio.com and install with dpkg -i or rpm -i.

04

Android SDK & emulator

React Native on Linux requires Android Studio to manage the SDK and create virtual devices. There is no iOS simulator on Linux — use a physical iPhone with Expo Go, or focus on Android development.

Step 1 — Install Java 17

bash — Debian / Ubuntu 
sudo apt install -y openjdk-17-jdk
java -version   # → openjdk version "17.x.x"

Step 2 — Install Android Studio

bash 
# Using snap (easiest, works on most distros)
sudo snap install android-studio --classic

# Or download the .tar.gz from developer.android.com/studio
# and extract to ~/android-studio, then run:
# ~/android-studio/bin/studio.sh

Step 3 — SDK components inside Android Studio

Open Android Studio → More Actions → SDK Manager → SDK Platforms tab → check Android 14 (API 34). Then SDK Tools tab → check: Android SDK Build-Tools, Android SDK Platform-Tools, Android Emulator, Android SDK Command-line Tools.

Step 4 — Create an AVD (emulator)

Android Studio → More Actions → Virtual Device Manager → Create Device. Pick Pixel 7 (or similar), select API 34 system image, click Finish. Launch the emulator once to confirm it boots.

Step 5 — Set environment variables

bash — add to ~/.bashrc or ~/.zshrc 
# Java
export JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64

# Android SDK (adjust path if you used a different install location)
export ANDROID_HOME=$HOME/Android/Sdk
export ANDROID_SDK_ROOT=$ANDROID_HOME

# Add platform-tools and emulator to PATH
export PATH="$PATH:$ANDROID_HOME/emulator"
export PATH="$PATH:$ANDROID_HOME/platform-tools"
export PATH="$PATH:$ANDROID_HOME/cmdline-tools/latest/bin"

# Reload
source ~/.bashrc
VariableTypical value on UbuntuPurpose
JAVA_HOME/usr/lib/jvm/java-17-openjdk-amd64React Native Gradle build
ANDROID_HOME$HOME/Android/SdkExpo CLI finds SDK tools
PATH addition$ANDROID_HOME/platform-toolsadb device commands
bash — verify 
adb version          # → Android Debug Bridge version 1.0.4x
emulator -list-avds  # → lists your virtual device name
⚠️ If Android Studio was installed via snap, the SDK may be at ~/snap/android-studio/current/android-sdk. Check Settings → Android SDK → SDK location inside Android Studio for the exact path.

Project setup

Extract the ZIP you downloaded, then install dependencies.

bash 
# Extract the archive
unzip ViztraBoard_Mobile_v1.0.zip
cd vizta-board-mobile

# Install all dependencies (takes 1–3 min first time)
npm install

# Verify Expo CLI is accessible
npx expo --version   # → 0.18.x or similar

Open the folder in VS Code:

bash 
code .

VS Code will detect the TypeScript project. When it prompts "Use workspace TypeScript version?", click Allow to use the project's own node_modules/typescript.

06

Configure API keys

Two placeholder keys must be replaced before the app will boot. Both are in the project root.

Clerk publishable key
app.json → extra.clerkPublishableKey
Replace pk_test_REPLACE_WITH_YOUR_CLERK_KEY
Get key ↗
Stripe publishable key
App.tsx → STRIPE_KEY constant
Replace pk_test_REPLACE_WITH_YOUR_STRIPE_PUBLISHABLE_KEY
Get key ↗
API base URL
app.json → extra.apiBaseUrl
Point to your Django backend (or http://10.0.2.2:8000/api/v1 for local)
app.json
💡 10.0.2.2 is the Android emulator's alias for your Linux machine's localhost. Use it when pointing the app at a local Django dev server.
⚠️ Never commit real keys to version control. Add .env to .gitignore and consider using expo-constants with a local .env file + dotenv for local development.
07

Run the app

Start the Expo dev server, then choose how to view the app.

bash — start dev server 
npx expo start

This opens the Expo dev menu in your terminal. Press one of these keys:

🤖 Android emulator

Make sure the AVD is already running (start it from Android Studio's Virtual Device Manager first).

Press a in the Expo terminal

📱 Physical Android

Enable USB Debugging on your phone. Connect via USB. Run adb devices to confirm it's recognized.

Press a in the Expo terminal

📲 Expo Go (WiFi)

Install Expo Go on any phone. Scan the QR code shown by the dev server. Phone and laptop must be on the same network.

Scan QR code with Expo Go

🌐 Web preview

Limited fidelity (no native modules), but useful for logic and layout work without a device.

Press w in the Expo terminal
💡 Press r in the Expo terminal to reload, j to open the Expo debugger, m to toggle the in-app dev menu on device. For a full native build (required before submitting to Play Store), use npx expo run:android — this requires Android Studio's build tools to be on PATH.
08

Common issues

ANDROID_HOME is not set
# Check env is exported from the correct shell file
echo $ANDROID_HOME
# If blank, re-source your shell config or log out and back in:
source ~/.bashrc
Emulator not found / adb devices shows nothing
# Start AVD from Android Studio OR from CLI:
emulator -avd Pixel_7_API_34 &

# For USB device: enable USB debugging + trust this computer
adb kill-server && adb start-server
adb devices
Metro bundler port conflict
# Kill whatever is on port 8081
npx kill-port 8081
npx expo start
node_modules issues / clean install
rm -rf node_modules .expo
npm install
npx expo start --clear
Clerk key error on startup
# Ensure app.json extra field is set correctly:
"extra": {
  "clerkPublishableKey": "pk_test_YOUR_REAL_KEY_HERE",
  "apiBaseUrl": "https://api.viztaboard.com/api/v1"
}
expo-secure-store crash on web
# expo-secure-store is native-only — don't use web target (w) for auth testing.
# Use Android emulator or Expo Go instead.
💡 Run npx expo doctor at any time — it checks your environment (Node version, Android SDK, package versions) and flags mismatches with one command.
