VS Code Dev Setup

Vizta Board API — Django 5 + DRF backend

✓ Python 3.12 Django 5.0.9
Get running in 5 steps
  1. 1
    Open the project
    Open the vizta-board-api folder in VS Code. When prompted, click Install All to install the recommended extensions.
  2. 2
    Create the virtual environment
    Terminal
    python -m venv .venv
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate            # Windows
pip install -r requirements.txt -r requirements.dev.txt
  3. 3
    Select the interpreter
    Press ⌘ Shift P → Python: Select Interpreter → choose .venv/bin/python.
  4. 4
    Start infra & migrate
    Terminal
    cp .env.example .env       # fill in secrets
docker compose up db redis -d
python manage.py migrate
python manage.py createsuperuser
  5. 5
    Launch the API
    Press F5 and choose Django: runserver. The API starts at http://localhost:8000/v1/ with the debugger attached.

All settings are pre-written to .vscode/settings.json in the project. No manual configuration needed — just open the folder.
Format on save (Ruff)
.vscode/settings.json — key entries
"[python]": {
  "editor.defaultFormatter": "charliermarsh.ruff",
  "editor.formatOnSave": true
},
"editor.codeActionsOnSave": {
  "source.fixAll.ruff": "explicit",    // auto-fix lint issues
  "source.organizeImports.ruff": "explicit"  // isort on save
},
"editor.rulers": [100]               // matches ruff.toml line-length
Django settings module (env auto-set)
"python.envFile": "${workspaceFolder}/.env",
"terminal.integrated.env.osx": {
  "DJANGO_SETTINGS_MODULE": "config.settings.development"
}
Important: Copy .env.example → .env and fill in your secrets before running anything. VS Code reads this file automatically for interpreter and terminal sessions.
Type checking (Pylance + mypy)
"python.analysis.typeCheckingMode": "basic",
"python.analysis.extraPaths": ["${workspaceFolder}"],
"mypy-type-checker.args": [
  "--ignore-missing-imports",
  "--follow-imports=silent",
  "--strict-optional"
]
Test discovery (pytest)
"python.testing.pytestEnabled": true,
"python.testing.pytestArgs": ["--no-header", "-rN"],
"python.testing.autoTestDiscoverOnSaveEnabled": true
Press F5 or open Run & Debug (⌘ Shift D) and choose a configuration.
Available launch configurations
🚀
Django: runserver
Starts the API on port 8000 with the debugger attached. Uses --noreload so breakpoints work correctly.
http://localhost:8000/v1/
⚙️
Celery: worker
Runs a Celery worker with --pool=solo so you can step through tasks with breakpoints.
celery -A config worker --pool=solo
🕐
Celery: beat
Starts the periodic task scheduler using DatabaseScheduler.
celery -A config beat --scheduler DatabaseScheduler
🐚
Django: shell
Opens manage.py shell in the integrated terminal, with the debugger attached.
python manage.py shell
🧪
pytest: current file
Runs pytest on the file currently open in the editor with -s so prints show through.
pytest ${file} -v -s
🔗
Compound: API + Worker
Launches Django runserver and Celery worker simultaneously in two debug sessions.
Full stack: API + Worker
Attach to Docker container
Useful when running inside Docker Compose. Add this to the API service in docker-compose.yml:
docker-compose.yml — api service command override
command: python -m debugpy --listen 0.0.0.0:5678
         --wait-for-client manage.py runserver 0.0.0.0:8000 --noreload
ports:
  - "8000:8000"
  - "5678:5678"  # debugpy port
Then use the Python: attach launch configuration (maps local code to /app in the container).

REST Client — quick API test
Create an api.http file to test endpoints from inside VS Code:
api.http
@baseUrl = http://localhost:8000/v1
@token = <clerk-jwt-here>

### List billboards
GET {{baseUrl}}/billboards/
Authorization: Bearer {{token}}

### Create booking
POST {{baseUrl}}/bookings/
Authorization: Bearer {{token}}
Content-Type: application/json

{
  "billboard": "<uuid>",
  "start_date": "2026-11-01",
  "end_date": "2026-11-14"
}
Click Send Request above each block — the response appears in a split panel.

Common workflows
Adding a new app
python manage.py startapp <name> apps/<name>
Then add 'apps.<name>' to INSTALLED_APPS in config/settings/base.py and wire URLs in config/urls.py.
Debugging a Celery task
Use the Celery: worker launch config with --pool=solo. Set a breakpoint inside the task function. Call the task with .delay() from the Django shell or a view.
Checking migration state
python manage.py showmigrations — lists applied (✓) and pending migrations per app. Run the django: migrate task to apply them.
Opening Swagger docs
Navigate to http://localhost:8000/docs/ for Swagger UI or /redoc/ for ReDoc. The schema is auto-generated from DRF viewsets via drf-spectacular.
