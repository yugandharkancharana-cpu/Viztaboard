Automated Test Suite Reference

Complete specification of unit and integration tests for the Vizta Board API. This document is the authoritative reference for test coverage, naming conventions, and the business rules each test validates.

133 Integration
12 Test Modules
8 Apps Covered
Test strategy: Tests are split into two tiers by pytest.mark. Unit tests (pytest.mark.unit) run with no database and no I/O — all external dependencies are replaced with MagicMock objects. They are fast, deterministic, and ideal for CI pre-merge gates. Integration tests (pytest.mark.django_db) use a real SQLite test database and DRF's APIClient with force_authenticate (no JWT overhead). Factory Boy factories build every fixture object, keeping tests independent and hermetic.
Unit — no DB, MagicMock dependencies
Integration — real DB, DRF APIClient
